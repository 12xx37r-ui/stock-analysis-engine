1. 해결한 엔진 문제
-------------------
A) 산업분류
- YG PLUS(037270)가 DART 631 코드만으로 소프트웨어·플랫폼으로 오분류되던 구조 수정.
- 631 전체를 소프트웨어로 묶지 않고 실제 사업/검증 매핑/세분 업종을 우선.
- YG PLUS 회귀결과: media_entertainment / 수동 종목매핑 / 신뢰도 100.
- 일반적인 631 정보서비스 기업은 자동으로 software_platform으로 몰지 않음.
- 명시적 소프트웨어·플랫폼 사업 키워드가 있는 경우에는 software_platform 유지 가능.

B) finalize_market_data import/test 불일치
- collectors/price.py에 이미 존재하던 공통 가격 후보/검증/캐시 계층을 collectors/market.py의 실제 실행 경로와 다시 연결.
- finalize_market_data()를 구현해 main.py와 screener.py에서 재무/기술 데이터 확보 뒤 현재가 교차검증을 수행.
- 기존 test_price_pipeline.py / validate_live_prices.py가 참조하던 함수가 실제로 존재하도록 구조 정합성을 복구.

C) 현재가 수집 호출 최적화
- KIS에서 정상 가격+거래량을 확보하면 Yahoo를 호출하지 않음.
- KIS가 없거나 사용할 수 없을 때만 Yahoo preferred market suffix 조회.
- preferred suffix가 사용할 수 없을 때만 alternate suffix를 조회.
- KIS 후보가 후속 재무/기술 교차검증에서 탈락한 특별한 경우에만 Yahoo 보조 재시도.
- 가격 캐시는 기존 구조를 재사용.

D) validate_output 경로 불일치
- 기본 검증 경로를 실제 게시 구조 data/latest/stocks/<종목코드>.json 우선으로 변경.
- 005930에 한해서 기존 output/samsung.json을 마지막 호환 fallback으로 허용.
- 존재하지 않는 output/005930.json 때문에 검증이 실패하던 문제 제거.

E) 게시 계약/점진 마이그레이션 정합성
- 산업프로필 기대버전 3.0.1로 통일.
- 현재가 검증 스키마 3.0.0 계약 확인 추가.
- 새로 생성되는 JSON은 엄격 계약 검증을 유지.
- 이미 읽을 수 있는 구형 게시 JSON은 인덱스에서 제거하지 않고 점진 갱신 대상으로 유지.
- 따라서 버전 변경 때문에 전체 종목을 한꺼번에 재생성해 GitHub/API 부하를 만들지 않음.
